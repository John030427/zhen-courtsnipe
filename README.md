# Zhen CourtSnipe

Windows 本机场地预约工作台：提前设置定时抢场，或持续关注退订后出现的空场。

当前版本包含完整场地列表修复、新手引导和无窗口后台启动。保留运行所需的平台适配，适用于特定预约平台，不支持任意网站。

## 开始前准备

先认准下面两个软件。企业微信中的预约页面使用的是**企业微信内置浏览器**，不是单独安装的浏览器，也不是本机工作台页面。

| 企业微信：打开并保留预约页面 | Clash Verge Rev：配置预约站点分流 |
| --- | --- |
| <img src="docs/assets/wecom-icon.png" alt="企业微信官方图标" width="64" height="64"> | <img src="docs/assets/clash-verge-rev-icon.png" alt="Clash Verge Rev 官方图标" width="64" height="64"> |
| 登录企业微信 → 工作台 → 场地预约 → 保持预约窗口打开 | 打开客户端 → 确认规则模式 → 按配置脚本提示添加规则 |
| [企业微信官网](https://work.weixin.qq.com/) | [Clash Verge Rev 官方项目与下载](https://github.com/clash-verge-rev/clash-verge-rev) |

图标取自各自官方站点或官方仓库，仅用于辨认软件；界面及图标可能随版本变化。

1. **打开并登录电脑版企业微信。** 从工作台进入官方场地预约页面，确认能正常看到场馆和场地。使用期间保持企业微信及预约页面打开，电脑保持联网、不休眠；自动恢复登录需要这个窗口。配置脚本提示重新打开客户端时，再按提示操作。
2. **准备好能自定义分流规则的代理客户端。** 推荐的自动获取流程使用 Clash Verge Rev；其他客户端先按 [配置指南](docs/CAPTURE_SETUP.md) 或交给本地 Agent 检查。Clash 路线需要规则模式，系统代理或 TUN 至少启用一个，并确认企业微信流量确实经过客户端。只针对预约站点添加规则，具体修改交给配置脚本逐项确认，不需要为了本工具开启全局模式。
3. **准备安装工具。** 命令行方式需要 Git 和 Python 3.12 或更新的正式版（64 位），用电脑上已有的就行，不需要特定小版本。使用 Agent 方式需先准备好有本机终端权限的 Claude Code / Codex，由它检查并协助安装。

以上代理准备针对**自动获取登录信息**的方式。不愿修改代理或证书时，可以尝试页面连接脚本，但官方客户端需要支持开发工具，且不能保证登录失效后自动恢复。安装好工作台也不等于已接入账号，仍需完成登录同步和只读验证。

## 快速开始

选择一种方式即可：熟悉终端就复制命令，不熟悉就把提示词交给自己电脑上的 Claude Code、Codex 等本地 Agent。

### 方式一：用 Git 命令安装

先装好这两个（电脑上已经有就直接用，不用卸载重装）：

- [Git](https://git-scm.com/download/win)
- [Python](https://www.python.org/downloads/windows/) **3.12 或更新的正式版**，64 位，不需要特定小版本。新装时勾选「Add python.exe to PATH」。

然后打开**普通的** PowerShell：开始菜单搜「PowerShell」直接打开，**不要**选「以管理员身份运行」。按下面四步执行，每一步成功了再做下一步。**第 3 步只是启动工作台，第 4 步才是首次配置自动获取登录；网页能打开不等于已经安装证书或接入账号。**

**第 1 步：下载到自己的用户文件夹**

```powershell
cd ~
git clone https://github.com/John030427/zhen-courtsnipe.git
cd zhen-courtsnipe
```

`cd ~` 先回到你自己的用户文件夹，项目会下载到 `C:\Users\你的用户名\zhen-courtsnipe`。少了这一步，PowerShell 可能停在 `C:\Windows\System32`，`git clone` 会报 `Permission denied`。

**第 2 步：建 Python 环境，安装依赖**

```powershell
py --version
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`py --version` 要显示 3.12 或更新。`py` 会用电脑上最新的 Python；提示找不到 `py` 时，把前两行的 `py` 换成 `python`。安装依赖要几分钟，结尾没有红色的 `ERROR` 就是成功了。

**第 3 步：启动**

```powershell
.\.venv\Scripts\python.exe launcher.py
```

看到 `OPEN http://127.0.0.1:8766/` 就成功了：浏览器会打开工作台，服务在后台运行，可以关掉 PowerShell。`127.0.0.1` 指的是**你自己这台电脑**，每台电脑都要在自己这里装好、启动。

第一次进入先看「设置 → 测试模式」：默认是真实预约，想先演练就打开测试模式。**到这里仅完成程序安装和启动，账号尚未接入，Clash 规则和本机证书也不会自动配置。**

**第 4 步：首次配置自动获取登录（使用 Clash Verge Rev 时）**

保持工作台运行，在**项目文件夹**的 PowerShell 中执行：

```powershell
.\setup-capture.cmd
```

也可以在资源管理器打开项目目录，**双击 `setup-capture.cmd`**。它与 `launcher.py` 的用途不同：`launcher.py` 只启动网页服务；`setup-capture.cmd` 才会启动自动获取登录的配置向导。

1. 向导先检测工作台（`127.0.0.1:8766`）、Clash/系统代理、8080 端口及本机 mitmproxy 证书；任何一步报错先停止，不要跳过。
2. **Clash Verge Rev** 选择 **A**：按提示确认开启抓取模式、安装**当前用户**的 mitmproxy 根证书和修改 Clash Verge 全局扩展脚本。每项配置都需要单独确认，不会自动帮你重启 Clash。安装本机 CA 会允许相应代理解密 HTTPS 流量，请确认来源可信且只用于自己的授权会话。
3. 打开 Clash Verge Rev，确保使用**规则模式**且已启用系统代理或 TUN；到「订阅」页**刷新/重新加载配置**。接着完全退出企业微信（包括托盘）再打开，从工作台进入学校官方预约页面。
4. 等向导显示已抓到登录信息，再进行一次**学校只读验证**。回到 `http://127.0.0.1:8766/`，检查「连接/采集 → 登录信息同步 → 学校验证」是否分别成功；**Token 同步不代表学校验证通过**。

**不是 Clash Verge Rev？** 如果使用的是 **Clash for Windows（CFW）**、Mihomo Party 等，请不要把 A 当作通用配置：它只自动适配 Clash Verge Rev。请参考 [其他代理客户端配置提示词](docs/LOCAL_AGENT_CAPTURE_PROMPT.md) 先检查再安全地配置；不希望修改代理/证书时，可在工作台使用页面连接脚本（须官方页面支持开发工具）。

**需要撤销吗？** 在项目目录双击 `undo-capture.cmd`，按提示撤销本工具的配置（也可在 PowerShell 执行 `.\undo-capture.cmd`）。证书、代理脚本和路由均有各自的撤销步骤。详细说明见 [自动获取登录配置指南](docs/CAPTURE_SETUP.md)。

**以后怎么用**

- 启动：双击项目文件夹里的 `start-workbench.vbs`，不会弹出任何窗口。
- 退出：网页左下角「退出服务」，或双击 `stop-workbench.cmd`。关掉浏览器不会停止服务。
- 更新到新版：先退出服务，在项目文件夹里运行 `git pull`，再运行一次第 2 步的最后一行，然后照常启动。
- **2026-10-25 以前下载过的旧克隆：** 公开仓库已使用当前源码快照重新创建，不再延续旧提交历史。请在另一个新目录克隆本仓库，不要在旧目录直接 `git pull`、强制同步或覆盖文件；旧目录中的配置和订单记录仍保留，不要删除。新克隆首次使用按本页步骤安装和检查账号状态；已经从新库克隆的目录以后可正常 `git pull`。
- **`setup-capture.cmd` 是首次账号接入的单独步骤**，不是每次启动都要运行；日常启动工作台不等于自动重新安装证书。

## 在另一台笔记本测试

1. 使用 Windows 10/11 x64，按上面「方式一」的三步安装，或者把完整提示词交给本地 Agent。用这台电脑自己的 Python（3.12 或更新），不照抄原电脑的安装路径。
2. 不要复制原电脑的 `config.toml`、订单记录、日志、Token 或 `.mitmproxy` 证书目录。新电脑使用自己的本机配置和证书。
3. 双击 `start-workbench.vbs`，在「设置」先确认测试模式，需要演练时手动开启。不要一上来就设置真实自动预约。
4. 查看新手引导，确认羽毛球「不限」显示 10 个场地、网球显示 7 个；登录接入前没有场地数据是正常的。
5. 在新电脑登录本人的企业微信并保持官方预约页打开，按配置说明接入。每台电脑都需单独检查代理分流、证书和账号状态；不要共用证书私钥。
6. 先核对「连接 → 登录信息同步 → 平台只读验证」各自状态，再测试只提醒的监控或模拟流程。不要在两台电脑上同时为同一账号运行真实预约任务，跨电脑不能共享本机的防重复记录。
7. 关闭浏览器后重开工作台应复用同一后台服务；结束试验时用页面「退出服务」。服务仅在本机监听，不要暴露到公网；关机或休眠会影响任务。

## 首次接入账号

完整步骤见 [快速开始](docs/QUICKSTART.md) 和 [自动获取配置说明](docs/CAPTURE_SETUP.md)。

| 你的情况 | 使用方式 |
| --- | --- |
| 使用 Clash Verge Rev，希望自动获取登录信息 | 在仓库目录运行 `setup-capture.cmd`，阅读提示并逐项确认 |
| 使用其他代理客户端，或配置脚本中途停止 | 使用 [给本地 Claude Code / Codex 的提示词](docs/LOCAL_AGENT_CAPTURE_PROMPT.md) |
| 不愿修改代理或证书 | 使用工作台设置里的页面连接脚本，前提是官方客户端开放开发工具 |

自动采集需要配置目标域名分流与当前用户证书。脚本会提示备份和撤销；保留这些记录，不要共享证书私钥或关闭安全软件。仅使用自己的合法账号并遵守预约平台规则。

接入成功要分别确认：**页面或采集通道连接 → 登录信息同步 → 学校只读验证通过**。同步成功不代表凭证永远有效。恢复能力取决于接入方式、官方登录会话和窗口状态；重新登录及人工验证需要本人完成。

## 定时抢场

1. 选择运动，在右侧打开「定时抢场」。
2. 填实际使用场地的日期、目标时段和候选场地。
3. 填平台的放号日期与时间。**放号时间和使用日期不同**；相对日期按设置当天解释。
4. 检查账号状态、费用条件及测试模式，再核对确认弹窗里的日期、星期、时段和场地顺序。
5. 确认后保持电脑开机、联网、不休眠，保留恢复登录需要的官方窗口。
6. 查看任务结果，并到官方「我的预约」核对最终订单。

适配平台常用流程为晚间放号后预约后天场地，以官方公告为准。场地表中的「20:00 自动切到后天并刷新」只刷新表格，不会代你创建任务。

工具不保证预约成功。查询成功只代表请求完成，不代表存在匹配空场。

## 持续监控

例如在 16:00–21:00 内寻找任意连续 1.5 小时，而不是要求五小时全部空闲。

1. 选择日期、场地范围和搜索时段。
2. 「预约时长」选 1 / 1.5 / 2 小时。
3. 初次建议选「只提醒我」；选「自动预约」表示满足条件时可能直接提交真实订单。
4. 设置「盯多久」，包括 24 小时。目标时段结束等条件可能提前结束任务，不会跨日自动更换目标。
5. 查看任务卡片区分查询、登录待恢复和结束状态；鉴权暂停期间不会下单。

关闭网页后后台可继续运行，网页弹窗提醒需要页面开着。全局测试模式与「只提醒我」是不同设置。

## 两种运动同时使用

羽毛球和网球各有独立任务，共享账号、请求预算及下单保护。同一天两个运动时段不能重叠，同一运动不能同时运行定时抢场和监控。并行不保证同时预约成功。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `git clone` 报 `Permission denied`（在 `System32` 里） | 先运行 `cd ~` 回到自己的用户文件夹再下载；用普通 PowerShell，不要用管理员 |
| 找不到 `py` 和 `python`，或版本低于 3.12 | 从 python.org 装 3.12 或更新的正式版（勾选 Add python.exe to PATH），重新打开 PowerShell；之前建失败的 `.venv` 文件夹删掉，再做第 2 步 |
| 安装依赖时出现红色 `ERROR` | 多半是 Python 太旧或网络中断。确认 `py --version` 后重新运行那一行；没装好之前不要启动 |
| 前一步失败了，后面几行也全报错 | 正常现象，后面的都依赖前一步。回到第一个报错的那一步解决，再往下做 |
| 本机网页打不开 | 检查启动提示、服务日志和端口占用，不随意结束其他进程 |
| 网页打开了，但登录状态 / 学校验证仍显示「未接入」，也没弹安装证书的窗口 | `launcher.py` 只负责启动服务；先确认是否已在项目目录运行 `setup-capture.cmd`，并按提示选择适合的接入方式。证书安装只在抓取路线、同意安装且前置检查成功后执行 |
| 官方页出现 502 | 检查本机代理及分流回环，按备份撤销本工具增加的配置 |
| 已连接但验证失败 | 看同步和验证时间，区分鉴权、网络和平台业务异常 |
| 登录失效后没有刷新 | 检查恢复选项、接入方式及官方登录窗口，必要时本人重新登录 |
| 没有匹配目标 | 核对具体日期、连续时长、候选场地和费用条件 |
| 结果未确认或订单冲突 | 先核对官方订单，不清空记录或连续重试绕过保护 |
