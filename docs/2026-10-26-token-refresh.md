# 放号前登录更新

启用设置中的“放号前刷新登录，失效时自动恢复”后，定时抢场会在放号前主动刷新官方窗口，等待新 Token 并验证。默认提前 120 秒：20:00 放号对应 19:58。自定义放号时间或提前量仍按任务设置执行。

## 使用条件

- 企业微信保持登录，官方预约窗口保持打开，现有刷新器能够识别窗口。
- 本地捕获链路已接入并成功捕获过登录信息。仅粘贴页面脚本、未接入代理捕获时，不会强行整页刷新。
- 自动恢复开关须已启用；升级不会擅自修改开关、测试模式或预约目标。
- 任务应提前设置。临近放号才启动会压缩刷新时间，不能保证赶上。

验证旧 Token 成功不等于续期。本次准备必须确认新值、认证版本更新且验证成功；无法完成则明确提示并停止准备，不继续冒险下单。登录过期需要重新登录时，仍需本人操作。

同一放号时间的两个运动共用准备结果。鉴权失败后复用已完成的恢复验证，避免重复查询。长轮扫描不再额外等待完整轮间间隔，但每秒一次的共享请求预算和服务端退避仍保留。

## 离线验收

在隔离的 `SUSTECH_DATA_DIR` 下运行：

```powershell
python -m unittest discover -s tests -p test_auth_keeper.py
python -m unittest discover -s tests -p test_rush_engine.py
node tests/check_inline_scripts.cjs
```

这两组测试共 45 项，使用模拟响应，不发送官方查询、验证码或订单。实际运行新代码前，需要在没有抢场或监控任务时重启后台服务。
