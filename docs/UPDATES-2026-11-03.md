# 2026-11-03 更新

- 持续监控自动预约：在单日期、单目标时段下，找到目标起点的连续空场后即可进入预约复查，减少等待后续场地扫描的时间。保持场地优先顺序；多日期、多目标、只提醒模式继续完整扫描。接口通过 `scan_short_circuited` 标记提前结束的扫描。
- 对平台明确返回的“当天预约总时长超过上限、剩余可预约分钟数”拒绝响应，记录为业务失败并停止当前任务，提示修改预约时长。不再因该响应使用 HTTP 500 就一律记录为订单结果未知。
- 其他未知 500、通用系统异常、响应信息矛盾或不完整，继续保留结果待核实保护。已有待核实记录不会自动清除或迁移。
- 停止提示区分登录问题和订单问题，并展示具体下单失败原因。订单未确认时提示核对官方订单；刷新登录不会重置历史任务或解除订单保护。

更新代码后，后端修改需在没有任务运行时重启服务；前端刷新页面加载。

验证：公开版本 52 项离线测试通过，内联及外部 JavaScript 语法检查通过，订单/登录恢复提示回归通过。未进行真实下单测试，未增加请求频率或并发，也未跳过下单前复查。
